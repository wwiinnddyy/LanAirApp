# 轻应用收录标准

本文档定义了 LanAirApp 官方市场收录轻应用（AirApp）的审核标准。所有提交收录申请的轻应用都需满足以下条件。

## 一、必要条件（必须满足）

以下条件任一不满足，收录申请将被直接拒绝。

### 1.1 API 版本合规

- 引用 `LanMountainDesktop.AirAppSdk`，`airapp.json` 中 `apiVersion` 主版本号为 `1`（当前为 `1.0.0`）
- 入口类标注 `[AirAppEntrance]`，继承 `AirAppBase`，实现
  `Initialize(HostBuilderContext, IServiceCollection)`
- 组件、设置页、窗口、导出契约一律通过 `Initialize` 中的 `IServiceCollection` 扩展注册
  （`AddAirAppComponent`、`AddAirAppSettingsSection`、`AddAirAppWindow`、`AddAirAppExport`）
- 不再使用 `LanMountainDesktop.PluginSdk` 的任何类型

### 1.2 包格式正确

- `.laapp` 包为合法的 ZIP 压缩包
- 包内包含 `airapp.json`，且 JSON 格式合法（不是旧的 `plugin.json`）
- `airapp.json` 中 `id`、`name`、`author`、`version`、`apiVersion`、`entranceAssembly` 字段非空
- `entranceAssembly` 指向的程序集在包内存在
- 包内不包含 `LanMountainDesktop.AirAppSdk.dll` 与 `LanMountainDesktop.Core.dll`（由宿主提供）
- 包内不包含无关的开发产物（`obj/`、`.vs/` 等）

### 1.3 GitHub Release 可达

- 仓库为 `github.com` 上的**公开**仓库
- 最新 Release 中包含 `.laapp` 后缀的 Asset
- Release Tag 格式为 `v<版本号>`（如 `v1.0.0`）

### 1.4 本地化

- 提供 `Localization/zh-CN.json`（中文）
- 提供 `Localization/en-US.json`（英文）
- 本地化文件 JSON 格式合法
- 关键 UI 文本均有对应的本地化 key

### 1.5 基本功能可用

- 能在 LanMountainDesktop 中正常加载
- 不会导致宿主崩溃或严重性能问题
- 桌面组件（如有）能正常显示
- 设置页（如有）能正常打开和操作

### 1.6 共享契约已登记

- `airapp.json` 中 `sharedContracts` 声明的每个契约，都必须在
  `airappmarket/registry/official-airapps.json` 的 `contracts` 数组中有对应条目，
  且契约 DLL 已提交到 `airappmarket/contracts/<契约ID>/<版本号>/`
- 未登记的契约会让轻应用装得上、载不起来，Validator 会直接拒绝这样的索引

## 二、推荐条件（强烈建议满足）

以下条件不满足不会直接拒绝，但会影响审核优先级和通过概率。

### 2.1 主题适配

- 亮色主题下显示正常
- 暗色主题下显示正常
- 主题切换时无视觉异常

### 2.2 外观系统

- 使用 `IAirAppAppearanceContext` / `AirAppAppearanceSnapshot` 消费外观信息
- 使用 `AirAppCornerRadiusPreset` 处理圆角（而非硬编码）
- 组件尺寸自适应（响应 CellSize 和 Bounds 变化）

### 2.3 市场元数据

- Release 中包含 `market-manifest.json` Asset
- 图标清晰且与功能相关

### 2.4 代码质量

- 代码结构清晰，职责分离
- 无明显的内存泄漏（如未释放的 Timer、未取消的事件订阅）
- 异步操作使用 `async/await`，不使用 `.Result` 或 `.Wait()`
- 线程安全（共享状态使用锁或并发集合）

### 2.5 文档

- `README.md` 包含功能说明
- `README.md` 包含安装和使用说明
- `README.md` 包含开发/构建说明（如适用）

## 三、拒绝条件（满足任一即拒绝）

### 3.1 安全问题

- 包含恶意代码（后门、挖矿、数据窃取等）
- 未经用户同意访问敏感数据（文件系统、网络、注册表等）
- 使用不安全的网络通信（HTTP 而非 HTTPS，不验证证书等）
- 包含硬编码的密钥、令牌或凭据

### 3.2 稳定性问题

- 加载后导致宿主崩溃
- 导致宿主内存持续增长（内存泄漏）
- 导致宿主 CPU 占用异常
- 阻塞宿主 UI 线程

### 3.3 合规问题

- `apiVersion` 主版本不为 `1`
- 包内仍是旧的 `plugin.json`
- `airapp.json` 格式不合法或字段缺失
- `.laapp` 包格式不正确
- 仓库不是 `github.com` 上的公开仓库
- ID 与已收录轻应用冲突
- ID 命名不规范（如包含空格、特殊字符）

### 3.4 质量问题

- 功能极不完整，无法实际使用
- UI 严重错乱或不可交互
- 本地化文本大量缺失

## 四、审核流程

### 4.1 自动校验（CI）

提交 PR 后，CI 会自动执行以下校验：

1. **Schema 可解析**：`airappmarket-index.schema.json` 本身是合法 JSON
2. **索引结构校验**（Validator）：
   - `schemaVersion` 为 `3.0.0`，`sourceId`、`sourceName`、`generatedAt` 非空
   - 每个 `pluginId` 非空且无重复
   - 每个条目的 `apiVersion` 主版本等于 `1`
   - `repositoryUrl` 为 `https://github.com/{owner}/{repo}` 形式
   - `releaseTag` 形如 `v1.2.3`，`sha256` / `md5` 长度与字符集合法
   - `packageSources` 恰好 3 个，按 `releaseAsset` → `rawFallback` → `workspaceLocal` 顺序
   - 条目引用的每个共享契约都在顶层 `contracts[]` 中存在

索引本身由 IndexBuilder 从各仓库的 Release 生成。不满足条件的条目会被跳过并打印原因，
不会进入索引，也就不会走到 Validator。

### 4.2 人工审核

维护者会进行以下审核：

1. **注册表条目审核**：字段是否完整、URL 是否可达、标签是否合理
2. **功能审核**：下载 `.laapp` 并在 LanMountainDesktop 中实际加载测试
3. **代码审核**：检查源码的安全性、代码质量和合规性
4. **UI 审核**：检查桌面组件和设置页的显示效果

### 4.3 审核结果

| 结果 | 说明 |
|------|------|
| **通过** | 满足所有必要条件，推荐条件基本满足，合并 PR |
| **需修改** | 满足必要条件但推荐条件有缺失，维护者留言说明需修改的内容 |
| **拒绝** | 不满足必要条件或触发拒绝条件，关闭 PR 并说明原因 |

## 五、已收录轻应用的维护

### 5.1 版本更新

已收录的轻应用发布新版本时，无需重新提交收录申请。IndexBuilder 会自动从 GitHub API 获取最新 Release。

### 5.2 下架条件

已收录的轻应用如出现以下情况，可能被从市场中移除：

- 长期无法加载或运行（与宿主新版本不兼容）
- 发现安全问题
- 仓库被删除或转为私有
- 作者申请下架

### 5.3 信息更新

如需更新已收录轻应用的注册信息（标签、能力提示、图标等），提交 PR 修改
`official-airapps.json` 中对应条目即可。

## 六、轻应用 ID 命名规范

ID 是全局唯一标识，建议遵循以下规范之一：

- 反向域名：`<域名反写>.<应用名>`，全小写，如 `com.example.myapp`
- 命名空间式：`<Brand>.<AppName>`，PascalCase，如 `LanMountainDesktop.SamplePlugin`

两种风格都可以，但必须：

- 不包含空格或特殊字符
- 与 `airapp.json` 中 `id` 完全一致
- 一旦收录就不要再改——ID 变了，宿主会把它当成另一个轻应用，已安装的用户不会收到更新

**示例**：

- `LanMountainDesktop.SamplePlugin` — 官方示例
- `com.voicehub.landesktop` — VoiceHub
- `Elysia.LanDesktopConnect` — Elysia
