# 轻应用收录指南

本文档说明如何把轻应用（AirApp）收录到 LanAirApp 官方市场。如果你是轻应用作者，请按以下步骤操作。

轻应用的唯一 SDK 是 `LanMountainDesktop.AirAppSdk`，API 版本 `1.0.0`，清单文件 `airapp.json`。
开发本身请看主仓库的
[轻应用开发文档](https://github.com/wwiinnddyy/LanMountainDesktop/tree/main/docs/01-AirApp%E5%BC%80%E5%8F%91)；
从旧 PluginSdk 迁移请看
[迁移指南](https://github.com/wwiinnddyy/LanMountainDesktop/blob/main/docs/AIRAPP_SDK_V1_MIGRATION.md)。

## 收录流程总览

```
开发轻应用 → dotnet build 产出 .laapp → 发布 Release → 提交收录申请 → 审核通过 → 索引刷新生效
```

## 第一步：确认前置条件

| 条件 | 说明 |
|------|------|
| `apiVersion` 为 `1.0.0` | `airapp.json` 中 `apiVersion` 主版本号必须是 `1`，否则宿主直接拒绝加载 |
| 仓库是公开仓库 | 必须是 `github.com` 上的公开仓库，私有仓库的 Release 用户下载不到 |
| GitHub Release 已创建 | Release 中上传 `.laapp` 文件作为 Asset |
| `.laapp` 包格式正确 | 包内包含合法的 `airapp.json` 和 `entranceAssembly` 指向的程序集 |
| 本地化文件完整 | 提供 `Localization/zh-CN.json` 和 `Localization/en-US.json` |
| README.md 存在 | 仓库根目录包含 `README.md` |
| 可正常运行 | 在 LanMountainDesktop 中实际加载并运行正常 |

## 第二步：获取 SDK 包

`LanMountainDesktop.AirAppSdk` 发布在 **GitHub Packages**。GitHub Packages 即使托管公开包，
还原时也必须提供凭据，所以你需要一个带 `read:packages` 权限的 Personal Access Token：

```bash
dotnet nuget add source https://nuget.pkg.github.com/wwiinnddyy/index.json \
  --name lanmountain --username <你的GitHub用户名> --password <PAT> --store-password-in-clear-text
```

仓库里的 `NuGet.config` 只登记源地址，**不要**把 token 写进去提交。CI 里用仓库 secret 注入。

## 第三步：打包

不需要单独的打包工具。只要项目引用了 `LanMountainDesktop.AirAppSdk` 且项目目录下存在 `airapp.json`，
SDK 的 MSBuild 目标会在 `Build` 之后自动打包：

```bash
dotnet build -c Release
```

产物是项目目录下的 `<程序集名>.<版本号>.laapp`，内容即构建输出目录的完整打包。

### .laapp 包应包含的内容

- `airapp.json` — 轻应用清单
- 主程序集 — 与 `entranceAssembly` 对应的 DLL
- 依赖程序集和 `.deps.json`
- `Localization/zh-CN.json` 和 `Localization/en-US.json`
- 其他运行时资源文件

> **注意**：`LanMountainDesktop.AirAppSdk.dll` 和 `LanMountainDesktop.Core.dll` 由宿主提供，
> 不应被打进包内。引用 SDK 时必须带上 `ExcludeAssets="runtime" PrivateAssets="all"`：
>
> ```xml
> <PackageReference Include="LanMountainDesktop.AirAppSdk" Version="1.0.0"
>                   ExcludeAssets="runtime" PrivateAssets="all" />
> ```
>
> 官方模板生成的项目已经这样写好了。

## 第四步：发布 Release

1. **Tag 格式**：`v<版本号>`，如 `v1.0.0`
2. **上传 Asset**：
   - **必须**：`<程序集名>.<版本号>.laapp`
   - **推荐**：`market-manifest.json`（补充市场展示元数据）
   - **推荐**：`sha256.txt` 和 `md5.txt`（校验和文件）

### market-manifest.json 示例

这个文件是**可选**的补充信息。版本、`apiVersion`、`entranceAssembly`、`sharedContracts`
一律以包内 `airapp.json` 为准，这里写了也不会覆盖它们。

```json
{
  "manifest": {
    "name": "My AirApp",
    "description": "一句话描述功能",
    "author": "YourName"
  },
  "compatibility": {
    "minHostVersion": "0.9.1"
  },
  "repository": {
    "iconUrl": "https://raw.githubusercontent.com/owner/repo/main/Assets/icon.png",
    "projectUrl": "https://github.com/owner/repo",
    "readmeUrl": "https://raw.githubusercontent.com/owner/repo/main/README.md",
    "homepageUrl": "https://github.com/owner/repo",
    "repositoryUrl": "https://github.com/owner/repo",
    "releaseNotes": "本次更新内容",
    "tags": ["tag1", "tag2"]
  },
  "capabilities": {
    "desktopComponents": [],
    "settingsSections": ["MySettingsSection"],
    "exports": [],
    "messageTypes": []
  }
}
```

## 第五步：提交收录申请

### 方式 A：提交 Pull Request（推荐）

1. Fork [LanAirApp](https://github.com/wwiinnddyy/LanAirApp) 仓库
2. 编辑 `airappmarket/registry/official-airapps.json`，在 `plugins` 数组末尾添加新条目
3. 提交 PR，使用 **"轻应用收录申请"** 模板填写信息

### 方式 B：提交 Issue

在 [LanAirApp Issues](https://github.com/wwiinnddyy/LanAirApp/issues) 中使用
**"轻应用收录申请"** 模板提交 Issue，维护者会代为编辑注册表。

## 第六步：等待审核

- CI 会自动校验 `index.json` 的合法性
- 维护者会审核功能、代码质量和合规性
- 如有问题，维护者会在 PR/Issue 中留言

## 第七步：索引刷新生效

审核通过并合并后，CI 会重新生成 `airappmarket/index.json`。

如果此时你的仓库还没有符合要求的 Release（或包内仍是旧的 `plugin.json`、`apiVersion` 主版本不是 `1`），
IndexBuilder 会**跳过**该条目并在日志里打印原因，其余条目照常刷新。补齐 Release 后重新触发刷新即可生效。

## 注册表条目字段说明

`airappmarket/registry/official-airapps.json` 中每个条目的字段说明：

### 必填字段

| 字段 | 类型 | 说明 | 示例 |
|------|------|------|------|
| `id` | string | 轻应用唯一标识，与 `airapp.json` 中 `id` 一致 | `"com.example.myapp"` |
| `repositoryUrl` | string | GitHub 公开仓库 URL（**必须为 github.com**） | `"https://github.com/owner/repo"` |

### 推荐字段

| 字段 | 类型 | 说明 | 示例 |
|------|------|------|------|
| `marketManifestAssetName` | string | Release 中市场清单 Asset 的名称，默认 `"market-manifest.json"` | `"market-manifest.json"` |
| `projectUrl` | string | 项目主页 URL | `"https://github.com/owner/repo"` |
| `readmeUrl` | string | README 文件的 raw URL | `"https://raw.githubusercontent.com/owner/repo/main/README.md"` |
| `homepageUrl` | string | 主页 URL | `"https://github.com/owner/repo"` |
| `iconUrl` | string | 图标 URL（支持 SVG/PNG） | `"https://raw.githubusercontent.com/owner/repo/main/Assets/icon.png"` |
| `defaultMinHostVersion` | string | 最低兼容宿主版本 | `"0.9.1"` |
| `tags` | string[] | 标签，用于分类和搜索 | `["music", "widget"]` |

### 能力提示字段

`capabilityHints` 对象声明轻应用提供的各类能力：

| 字段 | 类型 | 说明 |
|------|------|------|
| `capabilityHints.desktopComponents` | string[] | 桌面组件 ID 列表；IndexBuilder 会自动从包内 `airapp.json` 的 `components` 补全，通常留空即可 |
| `capabilityHints.settingsSections` | string[] | 设置页节名称列表 |
| `capabilityHints.exports` | string[] | 导出的共享契约接口名称列表 |
| `capabilityHints.messageTypes` | string[] | 消息总线中使用的消息类型列表 |

### 可选字段

| 字段 | 类型 | 说明 | 示例 |
|------|------|------|------|
| `releaseAssetName` | string | 指定要使用的 Release Asset 名称（当 Release 中有多个 `.laapp` 时） | `"MyAirApp.1.0.0.laapp"` |

## 共享契约

如果轻应用依赖共享契约（与其他轻应用共用的接口程序集），除了在 `airapp.json` 的 `sharedContracts`
中声明，还需要把契约登记到市场：

1. 把契约 DLL 放到 `airappmarket/contracts/<契约ID>/<版本号>/` 目录下
2. 在注册表的 `contracts` 数组中添加条目：

```json
{
  "id": "LanMountainDesktop.SharedContracts.YourContract",
  "version": "1.0.0",
  "assemblyName": "LanMountainDesktop.SharedContracts.YourContract.dll",
  "downloadUrl": "https://raw.githubusercontent.com/wwiinnddyy/LanAirApp/main/airappmarket/contracts/LanMountainDesktop.SharedContracts.YourContract/1.0.0/LanMountainDesktop.SharedContracts.YourContract.dll",
  "sha256": "<64位十六进制SHA256哈希>",
  "packageSizeBytes": <文件大小字节数>
}
```

宿主是从市场索引的 `contracts` 里解析并下载契约程序集的。索引里没有登记的契约会让轻应用
**装得上、载不起来**，所以 Validator 会拒绝任何引用了未登记契约的索引。

### 计算契约 DLL 的 SHA256

```powershell
$hash = (Get-FileHash -Path "YourContract.dll" -Algorithm SHA256).Hash.ToLower()
$size = (Get-Item "YourContract.dll").Length
Write-Host "SHA256: $hash"
Write-Host "Size: $size bytes"
```

## 完整示例

以下是一个完整的收录 PR 变更示例。

### 修改 `airappmarket/registry/official-airapps.json`

在 `plugins` 数组末尾添加：

```json
{
  "id": "com.voicehub.landesktop",
  "repositoryUrl": "https://github.com/wwiinnddyy/VoiceHubLanDesktop",
  "marketManifestAssetName": "market-manifest.json",
  "projectUrl": "https://github.com/wwiinnddyy/VoiceHubLanDesktop",
  "readmeUrl": "https://raw.githubusercontent.com/wwiinnddyy/VoiceHubLanDesktop/main/README.md",
  "homepageUrl": "https://github.com/wwiinnddyy/VoiceHubLanDesktop",
  "iconUrl": "https://raw.githubusercontent.com/wwiinnddyy/VoiceHubLanDesktop/main/Assets/icon.png",
  "defaultMinHostVersion": "0.9.1",
  "tags": [
    "voicehub",
    "music",
    "playlist",
    "radio"
  ],
  "capabilityHints": {
    "desktopComponents": [],
    "settingsSections": [
      "VoiceHubSettingsSection"
    ],
    "exports": [],
    "messageTypes": []
  }
}
```

### PR 描述

使用"轻应用收录申请"模板，填写：

- 轻应用 ID：`com.voicehub.landesktop`
- 仓库 URL：`https://github.com/wwiinnddyy/VoiceHubLanDesktop`
- 最新版本：`v1.0.0`
- apiVersion：`1.0.0`
- 最低宿主版本：`0.9.1`
- 附上桌面组件截图和设置页截图

## 常见问题

### Q：提交 PR 后多久能审核？

维护者会在有空时尽快审核。你可以在 PR 中 @ 维护者提醒。

### Q：审核不通过怎么办？

维护者会说明不通过的原因，你可以根据反馈修改后重新提交。

### Q：更新版本后需要重新提交 PR 吗？

不需要。注册表中只记录仓库 URL，IndexBuilder 会自动从 GitHub API 获取最新 Release。
你只需发布新 Release，然后触发 LanAirApp 的索引刷新工作流即可。

### Q：可以收录非 GitHub 仓库的轻应用吗？

目前不支持。`repositoryUrl` 必须是 `github.com` 上的公开仓库，因为 IndexBuilder 依赖
GitHub API 获取 Release 信息，而用户的宿主要能匿名下载 Release Asset。

### Q：`index.json` 需要手动修改吗？

不需要。`index.json` 由 IndexBuilder 自动生成，任何手动修改都会在下次刷新时被覆盖。
你只需修改 `official-airapps.json`。

### Q：如何触发索引刷新？

- 发布新 Release 后，可以通过 `repository_dispatch` 事件（类型 `official-plugin-released`）触发刷新工作流
- 也可以在 LanAirApp 仓库的 Actions 页面手动触发 `Refresh AirAppMarket Index` 工作流
- 当 `official-airapps.json` 变更合并到 `main` 时，刷新工作流会自动触发

### Q：我的条目在索引里不见了？

说明 IndexBuilder 跳过了它。去 Actions 日志里看 `Skipping '<你的ID>': ...` 这一行，
常见原因是：仓库没有 Release、Release 里没有 `.laapp`、包内还是旧的 `plugin.json`、
`apiVersion` 主版本不是 `1`、或仓库不是公开的。
